2026-09-26. Alcance: este checkout de Oracle. No se modificó código ni se inspeccionaron los repos Jam y LyraGASP. Las pruebas que crean archivos lo hicieron en `TemporaryDirectory`; las lecturas y búsquedas restantes fueron sobre este checkout. «Acepta» significa que pasó el lector indicado; cuando corresponde, se probó además `Medida.de_datos`. No se infiere que toda variante textual que acepta un parser forme una medida válida.

## Veredicto

**No hay una sola sintaxis de escritura expuesta.** Hay segunda entrada JSON explícita y enseñada en MCP; `oracle convertir` ofrece e imprime el árbol JSON de una medida o un caso; `oracle contexto` enseña accesores en forma de árbol JSON; el README presenta `.json` junto a `.oracle` y `.caso` como archivos de catálogo/corpus; la documentación MCP enseña `formato: json`. Dentro de la superficie, una macro invocada tiene dos cuerpos aceptados, y el impresor produce uno distinto del ejemplo de autoría empaquetado. La evidencia de `.caso` también tiene tabla y escape `fila {...}`; el impresor produce ambas según los datos. Hay una referencia obsoleta a un caso `.json` en la plantilla sensor-prosa.

El JSON de `oracle.json`, el de hechos para `juzgar`, el protocolo MCP/LSP, los fixtures y el AST canónico explicado como formato interno **no son por sí mismos** segunda sintaxis para escribir medidas/casos/relaciones. Sí lo son cuando una interfaz lo ofrece como **entrada de medida** o lo muestra bajo «con qué se escribe».
